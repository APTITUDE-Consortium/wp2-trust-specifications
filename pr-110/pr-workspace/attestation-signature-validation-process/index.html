    Attestation signature validation process

    This process validates the signature on an Attestation (including a Wallet Instance Attestation (WIA)) using the appropriate Signature/Seal Certificate (Sign/Seal Certificate). It is invoked during issuance and presentation flows. Sign/Seal Certificate chains are validated with the X.509 Certificate Chain Validation algorithm.

    The process is structured as follows.

    Input

    • The received Attestation and the signer certificate chain carried within it.
    • The type of Attestation, used to select the applicable trust source or scheme-specific validation rules.

    Outcome

    • The validated Attestation, or a validation failure.

    Process

    Base Signature Validation

    The procedure depends on the type of Attestation:

    1. Verify the Attestation signature with the Sign/Seal Certificate provided in the Attestation.
    2. Select and validate the applicable trust source: In this profile, for all credentials and attestation types, namely PID, Wallet Instance Attestation (WIA), QEAA, EAA and PuB-EAA, validate the applicable LoTE as defined in Trust Anchor Validation Process, and extract the appropriate Trust Anchor from the relevant entity's ServiceDigitalIdentity field.
    3. Extract the Sign/Seal Certificate chain from the Attestation and validate it against the obtained Trust Anchor using the X.509 Certificate Chain Validation algorithm.

    Note

    In an mdoc Attestation, the Mobile Security Object carries the Document Signer certificate in the x5chain header. In an SD-JWT VC Attestation, the issuer certificate chain is carried in the x5c header of the JOSE signature.
